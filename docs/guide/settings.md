# 设置：能调什么

管理弹窗的「设置」页签里列着**全部可调项**。每一项都写着它管什么、为什么默认是这个值。
这一页说明整体怎么用，以及哪些东西是**故意不给你调**的。

## 三项动作

- **改**：直接在控件上改。数字框填超范围的数会被自动夹到允许范围内（界面上会显示夹住后的真值），
  不用怕填错。
- **恢复全部默认**：把每一项都恢复出厂值。会先问你一次。
- **导出设置清单 JSON**：把全部可调项连同类型、默认值、取值范围、说明、以及**你现在的值**
  一起导出来。**这是给别人看的东西**——遇到问题贴这一段，比复述现象准确得多。

## 分组

| 分组 | 管什么 |
| --- | --- |
| 存储 | 聊天内容存在哪（文件 / 数据库 / 两者都有）、双写是否一改就落文件、保存后要不要自动导出 |
| 入库 | 打开没入库的聊天时要不要提醒 |
| 界面 | 分支树的展开方向、删分支要不要二次确认、操作提示气泡 |
| 结构图 | 图的方向、小地图与标签的节点数上限、分帧上屏的批大小、强制最小档 |
| 兼容 | 让酒馆与别的插件「列出聊天」时也看得到库里的聊天 |
| 接管 | 原生「创建分支 / 检查点」的内容闸门档位 |
| AI | AI 功能总开关、喂给模型的字数上限、每层截断字数、摘要长度上限 |
| 回收站 | 删除时留的副本保留几天 |
| 诊断 | 详细日志（排障时打开）|

## 几项值得单独说的

**存储模式**——这一项决定其他一切。默认是「JSONL 增强」：不动任何既有文件，最安全。
要拿到分支能力与结构图，需要用「当前聊天 → 转库」把聊天录进数据库。

**原生「创建分支/检查点」接管：内容闸门**——纯库/双写模式下，酒馆自己的「创建分支 /
创建检查点」要不要被本插件接管进库，取决于新文件的内容能不能对上父分支；这一项决定
「怎么算对得上」：

| 档位 | 含义 | 什么时候选它 |
| --- | --- | --- |
| 严格（默认） | 整行完全相同才算 | 不装消息改写类插件时 |
| 只比正文/说话人 | 忽略插件补的字段 | **装了变量框架 / 模板引擎这类会改消息的插件时选这个** |
| 不比内容 | 宿主说是分叉就照做 | 你清楚自己在做什么时 |

**默认「严格」是刻意保守**：它保持既有行为不变，换不换由你决定。
如果你发现「点创建分支没反应」，多半就是它挡住了——改成第二档。

**让「列出聊天」也看得到库里的聊天**——默认开。关掉后，酒馆与别的插件列聊天时
只看得到磁盘上的文件（纯库模式下那可能一个都没有）。

**强制最小档（诊断用）**——把结构图按最朴素的方式渲染（关小地图、关标签、分帧上屏）。
它的用途是**让你自己能验证「降级这条路是好的」**：不做成开关就只能改代码去测，那等于测不了。

**详细日志**——平时关着（刷屏没意义）；出问题时打开，把控制台里的内容贴出来就能定位。
它只影响「信息性」输出；**警告与错误一律照打**，不受这个开关影响。


## 故意不给你调的（以及为什么）

| 东西 | 为什么不暴露 |
| --- | --- |
| 「视口多小算小」这个阈值 | 它取决于你的弹窗大小，不是机器性能。改了只会得到一个和你屏幕不匹配的阈值 |
| 图节点的宽高 | 与字号绑定（字号写在样式里）。单独改尺寸会让文字溢出框 |
| 日志里原因的截断长度 | 只是防止日志被一长串堆栈灌满，没有用户语义 |
| 后端（Authority）的权限声明 | **权限要最小**。把它交给用户放大，等于把权限门禁交给用户 |
| 扩展的加载顺序、扩展 ID | 宿主契约，改了插件会被拒绝加载 |
| 「已静音的聊天」这份名单本身 | 由弹窗交互维护；设置里只暴露「一律不再提醒」这个总开关 |

上表是**刻意留白**，不是漏了。写在这里，是为了让你知道「有些东西找不到」是有原因的。

# 聊天记录零丢失

## 它做什么

保证**聊天头里的任何东西都不会因为用了本插件而丢** —— 包括**其他插件写进去的内容**。

这是本项目的第一条质量约束。

## 怎么用

你不需要做任何事。这是底层行为：**存的时候整份留、读的时候原样回显**。

## 具体保住什么

| 项 | 行为 |
| --- | --- |
| **其他插件的命名空间** | 整份保留。宿主的 `extensions` 下每个插件的命名空间**按名字逐项合并**——不是整体替换 |
| **聊天头里的其他字段** | 整份往返（`main_chat`、变量、书签引用等） |
| **字段级改动** | 落到库里，不丢 |
| **消息行本身** | 本插件**不得**给消息行**补默认字段**（"零改动"纪律） |

### 两条真机踩出来的规则

1. **`extensions` 不能整体替换**：所有插件的命名空间都挂在 `extensions.<插件名>` 下。
   如果整体替换它，宿主一次自带 `extensions` 的保存就会**把所有插件的命名空间一起抹掉**
   —— 真机症状是「时有时无的丢命名空间」。
2. **`main_chat` 属于某个聊天键，不属于家族**：它是"返回父聊天"的父线索。
   家族级内容是**所有键共用**的，把某个键的 `main_chat` 混进家族级，
   会让**别的键**也冒出"返回父聊天"。真机症状：在原生检查点聊天里切 swipe / 编辑消息，
   根聊天会**凭空多出一个指向自己的「返回父聊天」**，而且已经持久化。

## 边界与未做到

- 本插件只自管聊天头里的**两项**：自己的模型视图（`extensions.chatfilesys`）与**版本号**（`integrity`）。
  其余一切都属于「保留面」，插件只是代为保管。
- 模型视图只是一个**给宿主看的视图**——**真源在库**（见[三档存储与降级](/guide/storage-tiers)）。
- R0 的这条用例在**任何写路径改动后都必须重跑**，是回归门槛之一。

## 失败与降级时的表现

- 这是**保真**承诺而不是容错承诺：不做"丢了再补"。
- 若库不可用，写入按[三档存储与降级](/guide/storage-tiers)的规则处理，**不会静默丢数据**。

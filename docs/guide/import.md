# 导入旅程

## 它做什么

把**既有的 jsonl 聊天**收进库，变成家族。这是从"一堆互不相干的文件"走到"一个家族的多个分支"的入口。

## 怎么用

### 两个阶段（刻意的：检测不读全文）

| 阶段 | 做什么 |
| --- | --- |
| **检测** | 用搜索端点列出候选、按文件名过滤 —— **不读全文**（聊天文件可能很大） |
| **执行** | 才**逐文件读**，并逐个文件回报进度 |

### 单个文件的处理顺序

```
读源 → 算每行的内容指纹 → LCP 对齐合并 → 分块写入（500 行/批）
     → 快照进回收站 → 删源
```

**关键安全约束**：**删源之前必须先成功移进回收站**。顺序反了就是不可逆的数据丢失。

### 合并语义（指纹对齐）

- 内容指纹由消息的**归一化文本**（去 BOM、统一换行、去首尾空白）算 sha256；
- **完全相同**的内容 → **幂等去重**，不会重复导入；
- **前缀相同、之后分叉** → 分叉部分挂成**子分支**；
- 指纹相同但内容有疑 → **二重校验**后再定。

> 上面这条是**按聊天键对得上**时的走法（同一个聊天被更新后重新导入）。
> 对不上的走下面这条。

### 合并语义（同一个家族的不同版本）

按聊天键对不上时，插件会在**本角色已有的家族**里逐层比对，判断这份文件是不是「同一段历史的一个版本」。

- **只用内容判断**。两层是不是同一层，看它们的正文、以及该层自己带的多个版本有没有对上。
  **不看**时间戳、文件名、聊天 ID、名字像不像 —— 这些在真实数据里都会变，实测都不可靠。
- **判为同族就并进去**：被改动的层变成**该层的 swipe**，两个版本都在，你在聊天里用左右箭头切；
  不足以判为同层的层，两边都留着，成为分叉。**任何一份都不会丢。**
- **判不了就不猜，交你点选**：证据不够时**不合并**，导入结束会打开一张**候选确认清单**
  （官方弹窗）：每个候选列出文件名、疑似家族与逐层依据，你可以逐条
  「并入该家族」（只对该文件再走一次导入，源文件处理与本次导入同一选择；失败可重试）
  或「保留独立」（什么都不做）。全部处理完自动收窗；直接关窗 = 其余全部保留独立。
  明细同时写进浏览器控制台。宁可分成两个家族，也不做猜测性合并。
- **偏移极大（内容几乎不重合）会被拒绝合并** —— 这是**设计行为，不是缺陷**。
- **比对范围有上限**：只看**最近更新的前 20 个家族**（设置里可调）。超出上限时结果里会说明
  「只比了最近 N 个」，不会静默漏掉。
- **可以关掉**：设置里「智能家族合并：模糊探测」关掉，即回到只按聊天键对上。

## 边界与未做到

- **中间删层/插层之后会退化成「分叉」**：两侧的层号从那之后就对不上了，插件把其后的层当分叉处理，
  **内容各存一份**。零丢失，但会多占空间 —— 这是对齐判据与数据结构共同决定的上限，不是实现取巧。
- **候选点选界面还没做**：证据不足时只有一句提示 + 控制台明细，还不能在界面上逐份点选确认。
- **超大聊天有护栏**：单侧超过 2000 层时不逐层对齐，直接列为「判不了」。

- **本插件自己的隐藏容器绝不会被当成存量聊天导入**（有前缀过滤）——
  否则会把库存储自己喂回自己。
- **失败安全**：任何一个文件导入失败 → 记入「失败」列表，**不阻断其余文件**；
  结果在弹窗里统一汇报。
- **只做合并、不做覆盖**：已存在的内容按指纹去重，不重写既有分支。
- **导入是不可逆的操作路径**（源文件会被移进回收站后删除）——
  但回收站里有快照，可还原。
- **首次用户旅程实测尚未完成**（用真实聊天从导入走到换家族的完整一遍，见[路线图](/dev/roadmap)）。

## 失败与降级时的表现

- **写失败 → 不删源**（因为删除在移入回收站成功之后），最坏情况是"没导进去"，不是"源没了"。
- 逐文件的状态可查：成功 / 失败 / 跳过，且**失败原因如实记下**，不糊成一句"导入失败"。
- 库不可用时整条导入路径**不启动**，并明确提示当前存储档位（见[三档存储与降级](/guide/storage-tiers)）。

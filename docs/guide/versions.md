# 每层版本

## 它做什么

管理**某一个楼层上的所有版本**——不只是当前正看着的那一个。

概念上，一个楼层的「全部版本」是 **swipe 组 × 组内 swipe** 的展平：

- **当前组**（本聊天键所在分支在该层引用的那个组）→ 它的内容就是**界面上的那条消息**（body 行），
  组内版本 = 宿主原生的 `swipes` 数组。
- **别的组** → 折叠在家族模型里，组内版本是各自的一份列表。

所以「切到别的组」= 切分支；「在当前组里换一个」= 纯粹的 swipe 切换，**不切分支**。

## 怎么用

### 版本按钮

消息旁会出现一个**版本按钮**——**仅在该层的 swipe 组数 > 1 时**才出现（没有分叉的楼层不打扰你）。

### 版本弹窗的四项能力

| 能力 | 说明 |
| --- | --- |
| **预览** | 看该层所有版本的内容，不用逐个切过去 |
| **切换** | 把某一版变成当前可见内容 |
| **多选删除** | 勾多条一起删（**至少保留一个**） |
| **重排** | 交换两个版本的位置，正文与元数据一起搬 |

### 四条必须保住的语义（实现依据）

这四条不是我们自己发明的，是宿主原生语义 + 交互设计参考的共同结论：

1. **写前先快照**——「**活的正文才是真身**」：内存里被编辑或生成过的正文才是最新的，
   副本数组可能滞后。任何会改动版本列表的操作都必须**先跑快照**。
2. **切版本时不合并 `extra`**——`extra` 是**整份替换**而不是合并，
   防止上一版的媒体 / 推理 / 计数字段**泄漏**到新版本上。
3. **删除至少保留一个**；删掉的若是当前项，取**下一个**幸存者，末尾则取**前一个**。
4. **删除按降序逐条执行**，每步都落一次盘并发一次宿主原生的 `MESSAGE_SWIPE_DELETED` 事件
   ——这样按该事件维护下标的第三方扩展才能看到**真实的中间态**，不会看到下标跳变。

## 边界与未做到

- **只有「当前组」的版本可以直接改**（它的内容就是 body 行）。改动**别的组**要同时改行表，
  走的是另一条写路径。
- **没有 `swipes` 数组的行不会被补出字段**：单版本的行只改正文，**不顺手造出 `swipes`**
  ——这是「消息行零改动」纪律（本插件不得给消息行补默认字段）。
- **不删 `swipe_info[k].extra.token_count`**：本插件不得裁别人的字段（同上纪律）。
- **宿主没有「重排版本」的等价 API**，这一项是本插件提供的。
- 交互设计**参考**了外部同类插件，但**未引入其任何代码**。

## 失败与降级时的表现

- 参数非法时**先校验、后改动**——校验不通过就不动那一行（不会留下改坏的中间状态）。
- 越界、目标不存在、试图删到一个不剩，都会给出**说明原因的中文提示**，而不是静默失败。
- 预览/切换依赖库内模型；**body 比该层短**（库不自洽或投影不全）时退回折叠面读取，
  **不抛异常**。

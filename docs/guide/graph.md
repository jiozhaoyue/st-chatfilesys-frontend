# 图视图

> **状态：进行中。** 数据层与布局已交付，**渲染与交互尚未开始**——本页如实标出哪部分能用。

## 它做什么

把聊天家族变成一张**图**：节点是消息，边是"下一条接上一条"。用于跨会话地看整个角色名下聊天的走向。

这与[分支树](/guide/tree)不是一回事：分支树画的是**一个家族内的分支结构**，
图视图面向的是**跨聊天/跨会话**的更大范围。

## 怎么用

**目前还不能用**——渲染与交互（B4 及之后）尚未开发。已交付的是它可以依赖的地基：

| 已交付 | 内容 |
| --- | --- |
| **数据源抽象** | 统一产出会话清单、会话内容、图输入 —— 磁盘通道与库通道**两种实现同形产出**，上层不感知数据来自哪 |
| **图引擎** | 节点/边的构建；**节点身份 = 层号 + 内容指纹**（必须带层号，否则"后面又出现同样的台词"会塌成同一个节点造假环）；**多父保留全部入边**；增量失效**真读指纹** |
| **布局服务** | 算坐标。**在 Worker 里跑**（不占主线程）；真机实测：1000 节点 / 1019 边、主线程最大帧间隔 **78ms** |

## 边界与未做到

- **渲染、交互、小地图、渐进上屏、移动端手势全部未做**（B4 及之后）。
- **布局有两条路**，且**如实标出这次用了哪条**（这是刻意的可断言设计）：
  - `dagre`：分叉处更精致；
  - `layered`（迭代分层兜底）：当 dagre 撑不住时启用。
  **为什么需要兜底**：dagre 的深度优先遍历是**递归**的，链越长栈越深——
  而真实聊天的图**恰恰就是长链**（每条消息接上一条）。真机实测：浏览器 Worker 的栈更小，
  1000 条就爆 `RangeError`。所以"退回主线程"不是解法（主线程栈更大只是把爆点往后推，
  且会把界面卡住）。兜底算法**零递归**，长链本就是一条直线，与 dagre 结果一致。
- **布局结果会带上"为什么回落"的真实原因**，不静默降级（回落时的原因取自真实异常，
  超长栈会截断并注明截断）。

## 失败与降级时的表现

- **Worker 不可用 → 退回主线程**，且返回值**如实报告这次走了哪条路**（`worker` / `main`）。
  这一条是刻意设计的守卫：曾经的同类实现里，Worker **从未真正生效却没人知道**
  （每次都静默退回主线程），所以我们把"走了哪条路"变成**可断言的事实**。
- 图数据不完整时**不抛异常**，能算多少算多少。
- 布局超时或出错都**不会让界面挂住**——每条等待路径都有界。

# 图视图

> **状态：可用。** 数据层、布局、渲染与交互已交付并在真机跑通（四个宿主兼容见
> [宿主兼容](/dev/host-compat)）。本页如实标出能用到什么程度、哪里还没做。

## 它做什么

把聊天变成一张**图**：节点是消息，边是「下一条接上一条」。用于看**一个角色名下的多个聊天
是怎么分叉、又是怎么共用同一段开头的**。

这与[分支树](/guide/tree)不是一回事：

- **分支树**画的是**一个聊天之内**的分支结构（节点是分支）——「我有哪几条分支」
- **图视图**画的是**消息级**的结构（节点是消息）——「这几条线在哪里分、在哪里合」

两者数据同源，但粒度不同，界面上也各占一个页签。

## 怎么用

管理弹窗里点「结构图」页签。

- 滚轮缩放、拖拽平移、点节点选中
- 「适应窗口」把整张图装进视口；「重算」丢掉缓存重新读一遍
- 右下角**小地图**显示整图缩略与当前视野，点它可直接跳过去
- 选中节点后，下方「节点」区显示它的**上一节点 / 下一节点**（可点，点了把视口移过去）
- 左上角**状态条**显示：画出了多少节点与边、布局走的是 Worker 还是主线程、
  算法是 dagre 还是迭代分层、这次是重建还是复用缓存、各花了多少毫秒

**一条刻意的设计**：图上的节点只写「第几层、谁说的」，**不显示正文**。
正文只在你自己点开节点时才展开（走既有的版本展示层）。这样图始终是**结构**，
不会变成聊天记录的第二份副本。

## 共享前缀：它为什么值得单独说

同一段开头出现在多个聊天里时，图上**只有一个节点**，不是每份聊天各画一个。
所以长聊天换分支、复制聊天、拆聊天之后，图上看不出重复——这是图存在的主要理由之一。

被多个聊天共用的节点，选中后详情里会写「被 N 条会话共享」。

## 数据量大了会怎样

图会**按需降级**，而且**降级原因会写在界面上**（不是默默变朴素）：

| 情况 | 表现 |
| --- | --- |
| 视口较小 | 关掉小地图，把地方让给图 |
| 节点较多 | 不画边上的文字标签 |
| 节点很多 | 改为分帧上屏（每帧画一批），不会一次性卡住界面 |
| 系统开了「减少动效」 | 不做过渡动画 |

阈值可以在[设置](/guide/settings)里改；也有一项「强制最小档」用来自己验证降级本身是好的。

## 边界与未做到

- **节点正文不在图里**：要看内容得点开节点（设计如此，见上）。
- **图上不能直接改数据**：图是只读的视图；要删分支、切分支请用「当前聊天」页签。
- **布局有两条路**，且**如实标出这次用了哪条**（刻意的可断言设计）：
  - `dagre`：分叉处更精致；
  - `layered`（迭代分层兜底）：dagre 撑不住时启用。
  **为什么需要兜底**：dagre 的深度优先遍历是**递归**的，链越长栈越深——
  而真实聊天的图**恰恰就是长链**（每条消息接上一条）。真机实测：浏览器 Worker 的栈更小，
  1000 条就爆 `RangeError`。所以「退回主线程」不是解法（主线程栈更大只是把爆点往后推，
  且会把界面卡住）。兜底算法**零递归**，长链本就是一条直线，与 dagre 结果一致。

## 失败与降级时的表现

- **Worker 不可用 → 退回主线程**，且返回值**如实报告这次走了哪条路**（`worker` / `main`）。
  这一条是刻意设计的守卫：曾经的同类实现里，Worker **从未真正生效却没人知道**
  （每次都静默退回主线程），所以我们把「走了哪条路」变成可断言的事实，并印在界面上。
- **读不到数据时不会假装「这个聊天没有结构」**：图一个节点都没有、而当前聊天明显有内容时，
  会报一条 `CFS-N004`（「没读到」而不是「没有」），归因里带上数据源的真实说明。
  见[报错说明](/guide/errors)。
- 图数据不完整时**不抛异常**，能算多少算多少；布局超时或出错都**不会让界面挂住**。

# 三档存储与降级

## 它做什么

决定「库」**放在哪个后端**。插件启动时**自动挑当前可用的最高一档**，不需要你选。

## 怎么用

### 三档（按优先级）

| 档 | 后端 | 事实源在哪 | 说明 |
| --- | --- | --- | --- |
| **档 1** | **Authority SQL**（服务端数据库） | 服务端库 | 真分片库，性能最佳。需要装了 Authority 后端插件才可用 |
| **档 2** | **官方通道**（`/api/chats/*`） | 服务端，但借宿主的聊天容器 | 每家族 = 一个**隐藏聊天容器**；body 每行是一个楼层行 |
| **档 3** | **IndexedDB**（浏览器本地） | **仅缓存，非事实源** | 无服务端场景的会话级兜底；界面会提示「当前仅本地缓存」 |

选档是**特性检测**：档 1 初始化失败就退档 2，档 2 也不行就退档 3。
**任何一档不可用都不阻断使用。**

### 三档共用同一套契约

三档实现的是**同一个接口**，所以上层的接缝、图引擎、版本管理都不需要知道当前是哪一档：

```
listFamilies / loadFamily / createFamily / bindChatKey / renameFamily / deleteFamily
loadFloors / saveFloors / applyOps / saveModel
moveToTrash / listTrash / restoreFromTrash / deleteFromTrash
```

差异只在**落库手法**，语义统一由纯逻辑层（投影 → 应用补丁 → 按键写回）决定。

### 版本号（并发保护）

「库」带一个**家族级字符串版本号**，每次成功写生成一个新值。写入时：

- 入向版本号与库内值**字符串相等**才允许写；
- 不等 → 明确返回**冲突**（接缝映射为 `409`），由酒馆按它自己的规矩重拉重写；
- 调用方**没带**版本号（例如宿主原生保存不带）→ 不锁；
- 库内为空（家族还没写过）→ 放行首次写。

## 边界与未做到

- **档 1 需要装了 Authority 后端插件**（服务端插件，装在宿主的 `plugins/authority`），
  且它的 core 进程在跑。少了任一条就自动退档 2/3——不需要你手动选。
- **档 1 尚未做过「长期使用 / 多并发 / 性能基准」的验证**：功能路径已在真机上跑通
  （建档、写楼层、读回、回收站写入与清理），但**性能与并发还没有基线数据**。
- **档 3 不是事实源**：它只服务会话内读写，浏览器数据被清即丢失——用户资产的事实源在服务端。
- **回收站能力按档不同**：只有**档 1** 能列出回收站条目；另两档没有枚举接口，
  弹窗里会**直说不可用**，不假装空列表。
- 档 2 是「借宿主的聊天存储当 K/V 用」（一个隐藏聊天装一个家族），
  性能弱于档 1 属预期。

## 失败与降级时的表现

- 档 1 初始化失败 → 记一条带本插件前缀的日志（**带上真原因**，例如 `sdk-missing` / `init-failed: …`），
  **自动退档 2**；档 2 也失败 → 退档 3。
- 全程**不抛到用户面前**，聊天主路径不因后端不可用而失败。
- 冲突（版本号不等）**不是错误而是正常语义**：插件把冲突如实交回宿主，由宿主重拉重写。

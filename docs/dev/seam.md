# 接缝（fetch 拦截层）

## 它做什么

在宿主的聊天读写出口上装一层拦截：给全局 `fetch` 打补丁，只接 `/api/chats/*` 里的 9 条路由。
**读**——从库拼装出宿主认得的标准响应（`[header, ...messages]`，伪装成 jsonl）；
**写**——把宿主的写请求解包后落库，再伪造一个成功的回执。
其余请求**原样透传**，`headers` / `init` 全量传递，不打扰同页面上的其他插件。

只有**纯数据库**与**双写**两个模式会装接缝；**JSONL 增强**模式不装，
行为与改造前完全一致（这也是它作为默认值的原因）。

## 怎么用

### 拦下来的 9 条路由

| 路由 | 拦下来做什么 |
| --- | --- |
| `chats/get` | 库 → 拼成 `[header, ...messages]` 的合规响应（含分页 `has_more`） |
| `chats/save` | 整份落库 |
| `chats/append` | 追加 |
| `chats/patch` | 增量补丁（RFC 6902，可含 `/N/字段` 深路径；下标约定见[适配器契约](/dev/storage-adapter)） |
| `chats/rename` | 改名 |
| `chats/delete` | 删除 |
| `chats/meta` | 聊天头保留面（宿主与其他插件写进 `chat_metadata` 的内容） |
| `chats/meta/patch` | 只推版本号（防「该写的没写」） |
| `chats/get-delta` | 宿主原生的分页读 |

### 什么时候**不**拦（三种情况都原样透传）

1. **不是这 9 条路由** → 直接透传，等于没装。
2. **这个聊天没被收进库**（未命中家族）→ 透传，宿主原生行为不变。
3. **拦截处理中抛了异常** → 记一条 `[chatfilesys-seam]` 前缀的日志，然后**透传原生请求**。
   这一条是硬纪律（`L0-11`）：接缝的任何故障都不许把宿主的聊天功能带下去。

### 原生通道：`seam.native(...)`

绕开拦截、直接打真 fetch。**导入旅程读源 jsonl、删源文件必须走它**——否则会读到自己伪造的响应。
库模式下凡是「要跟真服务端说话」的地方都得显式用它。

### 卸载

`dispose()` 把 `fetch` 还原成原始实现，且**只有当前 `fetch` 仍是接缝自己那一层时才还原**
（避免把别人后装的补丁误摘）。

## 冲突怎么映射

版本号对不上不是「错误」，是**正常语义**：它表示「你手里那份已经过期了」。
所以接缝要把它如实交回宿主，让宿主按它自己的规矩重拉重写。

| 情形 | 结果 |
| --- | --- |
| 入向版本号与库内**相等** | 放行 |
| **不等** | 回 `{ ok: false, conflict: true }` + HTTP **409** |
| 入向**没带**版本号（例如宿主原生保存不带） | 不锁，放行 |
| 库内为空（这个家族还没写过） | 首次写，放行 |
| 补丁里的 `test` op 不通过（库内容与宿主的假设不符） | **409** |
| 其他失败原因 | **400**（宿主自行回退全量保存） |

**409 与 400 的区别要守住**：409 是「版本过期，重来一遍可能就成了」，
400 是「这次请求本身不合法，重试也没用」。

## 接管原生「创建分支 / 检查点」

未命中家族时还有一次接管机会。判定是**三重**的，任一不满足就透传（宁可不接管，也不猜错）：

1. **父线索**：请求头里宿主写的 `chat_metadata.main_chat` → 该键要能命中一个已有家族
2. **内容闸门**：正文行序列必须是父分支当前投影的**逐行前缀**
3. **类型**：分支名由宿主自动生成、不可改 → 名字里带 ` - Branch #<n>` 的算分支，其余算检查点

三条全过 → 在父家族里建一条分支 + 一条键绑定，然后回成功。**磁盘上不产生任何复制文件**——
这正是「原生按钮不再落复制文件」的实现位置。

## 边界与未做到

- **内容闸门是整行 JSON 全等**。装了会改写消息内容的插件（在消息里插标记之类的）时，
  闸门可能不相等 → **接管可能不触发**，退回原生行为（也就是说，那种情况下会落复制文件）。
  这是既有真机定论，不是没做完的东西，但它是一条真实的使用限制。
- **拦截面就是那 9 条路由**。宿主若经别的路径改聊天数据，不经过接缝——
  「穷举宿主持久化路径」没做过。
- **多插件共存未实测**：多个插件都补 `fetch` 时的先后与相互影响，属[路线图](/dev/roadmap)里的未做项。
- **接缝是进程级补丁**，装在全局 `fetch` 上，不是某个模块的局部拦截。

## 失败与降级时的表现

- **安装失败** → 记一条日志，宿主保持原生行为，返回的 `dispose` 是个空操作。
- **拦截处理异常** → 日志 + 透传原生请求；用户看到的是「这一下没走库」，不是报错。
- **适配器回冲突** → 409 交给宿主；用户侧的体感是宿主自己重拉重写，通常无感。
- **适配器整体不可用** → 不属于接缝的职责：选档阶段就已经逐级降级或退回 JSONL 增强模式
  （见[适配器契约](/dev/storage-adapter)）。

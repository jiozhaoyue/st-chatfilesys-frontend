# 测试基建

## 它做什么

两层测试，各管一段：

| 层 | 跑什么 | 怎么跑 | 依赖 |
| --- | --- | --- | --- |
| **单测** | `core/` 的数据层行为 | `node --test`，**直接 import 源码**，没有 mock 框架 | 无（纯 node） |
| **真机 e2e** | 界面与集成行为 | Playwright 驱动**真实宿主实例** | 一台跑着 Luker 的 Dev 实例 |

数据层之所以能这么测，是因为 `core/` 零 DOM 依赖（见[架构](/dev/architecture)）。
UI 与集成行为不在单测里伪造宿主，**一律在真机实例里做**——本仓不设独立演示页。

## 怎么用

### 三条最低验证（改动都要过）

```bash
# 1) 数据层单测（必绿）—— 当前 29 个测试文件 / 411 项
node --test tests/branches/*.test.mjs

# 2) 语法检查
node --check public/scripts/extensions/third-party/chatfilesys/**/*.js

# 3) 部署到实例后跑 e2e（宿主真实浏览器）
PYTHONIOENCODING=utf-8 python tests/e2e/<用例>.py
```

- **质量门 = 全绿**，没有覆盖率门槛。「绿」的含义是：单测全过 + e2e 全量过 + **归因零报错**。
- **`PYTHONIOENCODING=utf-8` 在 Windows 上是必需的**：宿主控制台默认 GBK，而断言明细里带
  `⎇`（版本按钮那个形状）等非 GBK 字符，不设这个变量会以 `UnicodeEncodeError` **崩在打印断言那一行**——
  那不是用例失败，是编码崩，很容易误判成功能坏了。

### e2e 怎么用（`tests/e2e/harness.py`）

harness 提供一台「已经理解了本插件」的驱动：`Runner.boot()` 起页面并静音入库提醒，
`ensure_popup()` / `popup_switch_tab()` / `click_action()` 走界面，`state()` / `model()` 读库内状态，
`wait_state()` / `wait_disk()` 做**轮询等待**。

用例按主题分文件（`test_*.py`）；**权威的用例清单就是 `tests/e2e/` 目录本身**
（`ls tests/e2e/test_*.py`），本页不复制一份会过期的名单。
同目录下的 `probe_*.py` / `recon*.py` 是**一次性探针**，不是回归套件。

## 硬纪律

1. **测试角色前缀 `__cb_e2e`，末尾清理，绝不触碰既有数据**。
2. **落盘核对**：内存断言之后必查一次服务端重拉的状态——防「内存对、磁盘错」的假绿。
3. **不许用固定 `sleep` 做断言**：用 `wait_state` / `wait_disk` 轮询。宿主高负载下固定等待不稳，
   会变成间歇性红。
4. **归因零报错**：页面错误按 `/third-party/<插件名>/` 归因，**本插件必须零归因报错**。
   宿主其他扩展的噪音（第三方 404 等）不计入——这是口径，不是放水。
5. **串行跑**：所有 e2e 用例共用同一台实例。并发跑会互相打断模式切换与聊天重载
   （实测过一次：`test_main_branch.py` 的第 ④ 项并发下失败、独占重跑即全绿）。
6. **跑之前要把插件目录同步到实例**：harness **不替你同步**
   （实例侧路径是 `data/<user-handle>/extensions/chatfilesys/`）。
7. **e2e 只对 Dev 实例跑**。Dev 与 Real 实例的宿主版本号完全相同、只有端口不同，
   没有别的区分依据——脚本指向 Real 侧就是操作真实聊天数据，不可逆。
8. **新增的守卫断言要变异实测**：写完把它依赖的实现撤掉，看它是否真的变红。
   不变红的断言等于没有断言。

## 边界与未做到

- **e2e 依赖一台本地实例**：没有实例就没有 e2e，所以 e2e 进不了「克隆下来就能跑」的 CI。
- **需要人工同步插件目录**（上述第 6 条），这一步目前不在 harness 里。
- **已知噪音基线**：冒烟用例的口径是 **4/5**（宿主其他扩展的 pageerror 噪音），不是回归。
- **跨三模式的行为一致性回归未做**（参数化矩阵）→ 见[路线图](/dev/roadmap)。
- **多插件共存实测未做**。
- **首次用户旅程实测未做**（用真实聊天完整走一遍：导入 → 聊天 → 分支 → 切版本 → 换家族）。
- **档 1（Authority SQL）没有真机验证**——它的适配器只有用 mock client 的单测。

## 失败与降级时的表现

- **单测红**：改动不合数据层约定，不该提交。
- **e2e 红**：先看是不是**并发/未同步插件目录**这两个已知环境原因，再怀疑功能。
- **归因报错**：本插件自己的页面错误**必须清零**；出现即视为回归。
- **编码崩溃**（`UnicodeEncodeError`）：加上 `PYTHONIOENCODING=utf-8` 重跑，这不是功能失败。
- **视觉截图**：只作**人工留证**用（用例把图落到 `tests/e2e/shots/`），断言一律代码化——
  不靠读图判断通过与否。

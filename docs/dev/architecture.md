# 架构

> 面向**要改这个扩展的人**。本页讲结构与不变式；逐文件的清单与命名/禁令细则属于**机向规范**
> （口径见[文档政策](/dev/docs-policy)），本站不复制，避免两处漂移。

## 它做什么

把「数据」和「界面」硬切开，让数据层能脱离浏览器跑测试。

```
public/scripts/extensions/third-party/chatfilesys/
├── manifest.json     扩展清单（宿主读它来加载）
├── index.js          唯一编排层
├── style.css         全部样式（类名前缀 chatfilesys-*）
├── core/             数据层：模型、纯函数、存储、接缝、图引擎
├── vendor/           第三方库的本地副本（原样不改）
└── ui/               视图层：只渲染 + 回调上抛
```

| 层 | 该放什么 | 不该放什么 |
| --- | --- | --- |
| `index.js` | 编排：能力检测、事件接线、弹窗生命周期、入口按钮、业务动作 | 可复用的逻辑（应下沉到 `core/`） |
| `core/` | 模型、纯函数、存储适配器、接缝、图引擎 | **任何 DOM 与宿主 API** |
| `ui/` | 渲染、事件绑定；数据一律由参数注入 | 数据变换（应在 `core/` 里做好） |
| `vendor/` | 第三方库**原样**副本（只在文件头记来源/版本/许可） | 改动库本身 |

依赖方向是单向的：`index.js` → `ui/` + `core/`，`ui/` → `core/`，而 **`core/` 不依赖任何一层**。

**为什么这么切**：`core/` 零 DOM 依赖，所以能在 node 里直接 `import` 源码跑单测——
今天的 29 个测试文件、411 项断言里，绝大部分就是这么跑的（不用 mock 框架，用真代码）。
反过来，宿主 API 只出现在 `index.js` 一个文件里，将来宿主改 API 时改动面是收敛的。

## 怎么用

**加一个功能，按这个顺序落**：

1. **先落 `core/`** —— 数据模型 + 纯函数 + 单测（`tests/branches/`，`node --test` 直接跑）
2. **再接 `ui/`** —— 渲染函数两形态：要么返回 HTML 字符串（调用方负责插入），要么接一个已存在的容器；数据全部经参数进来
3. **最后接 `index.js`** —— 拿宿主数据、调 core、把结果交给 ui、把动作挂到宿主事件上

**第三方库怎么进**：没有打包器，所以库必须以本地副本放进 `vendor/`，且**同一份文件要能在三种环境下加载**——
浏览器页面用 `<script>`、module worker 用副作用 `import`（**不能用 `importScripts`**，module worker 里没这个函数）、
node 单测用 `vm` 跑真库。做法是**库不自己加载自己**：`core/graph/layout.js` 只接受注入进来的 `dagre`，
由调用方按当前环境决定怎么把它弄进来。

**无构建步骤**：浏览器原生 ES Module 直载 + `manifest.json`，装完即可用。
扩展目录里的 `package.json` 只声明 `"type": "module"` 给 node 单测用，
宿主读的是 `manifest.json`，不受它影响。（这条对应仓库规则 `L1-MR-11`：装完即可用，不需要用户跑构建。）

## 边界与未做到

- **「三形态同构」在本仓落地为两形态。** 规则里的设想是「一套核心三种入口：独立 Web 页 / 宿主插件 / node 测试」。
  独立演示页已按**无包袱铁律**（2026-09-25）删除——它既不是真实实例、也不产生实例没有的东西。
  现在剩下**宿主插件**与 **node 测试**两个入口；`core/` 保持零 DOM 依赖正是为后一个入口。
- **`index.js` 是已知的集中点**（2000 行出头）。它是唯一编排层，宿主 API 全在这里——收敛带来的是
  「改宿主 API 只改一处」，代价是这个文件偏大。拆分的标准是「能下沉到 `core/` 的就要下沉」。
- **`core/` 不设运行时类型校验**（纯 JS，靠 JSDoc + 单测锁行为）；跨层传错形状的错误会在跑测试时暴露，
  而不是在写代码时被编译器拦住。
- **后端不在本仓**：Authority 数据库后端是另一个仓库的事，仓根的 `backend-plugin-spec.md` 是它的接入指导。

## 失败与降级时的表现

分层本身就是降级纪律的载体：

- **`core/` 不知道宿主存在**，所以宿主能力缺失时的判断只能发生在 `index.js`——那里的能力检测决定
  「这次少哪个功能」（见[宿主兼容](/dev/host-compat)）。
- **能力缺失不阻断加载**：任何一处检测失败都只记一条带 `[chatfilesys]` 前缀的日志，插件其余部分照常工作。
- **存储后端不可用**：由选档逐级降级处理，接缝与界面层都不感知（见[适配器契约](/dev/storage-adapter)）。
